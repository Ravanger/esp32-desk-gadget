# Troubleshooting

| Symptom | Likely cause | Fix |
| ------- | ------------ | --- |
| OLED stays black, Serial says "not found at 0x3C" | Wrong I2C address (some modules are 0x3D), SDA/SCL swapped, or I2C wired to the classic-ESP32 pins 21/22 or the C3's risky 8/9 | On the SuperMini, SDA must be GPIO 4 and SCL GPIO 5, and the sketch must call `Wire.begin(4, 5)`. GPIO 8 (strapping + onboard LED) and GPIO 9 (strapping + BOOT) are not I2C pins for this build. Run an I2C scanner sketch to find the real address. Also confirm VCC is on 3V3, not 5V. |
| DHT page says "No reading" / values never update | DATA on the wrong pin, VCC/GND swapped, or reads happening too fast | Check DATA → GPIO 3; confirm the module version (with pull-up) is used, or add a 10K pull-up between DATA and VCC for a bare sensor; keep the 2-second interval and the `isnan()` guard — frequent NaN bursts on a correctly wired DHT11 usually mean it is being polled too often somewhere. Note the sensor's ±2 °C / ±5 % RH accuracy: small disagreements with another thermometer are expected, not a fault. |
| Serial Monitor shows nothing at all | USB CDC On Boot is off, or the wrong board/port | Select "ESP32C3 Dev Module", enable Tools → USB CDC On Boot, and re-upload. The SuperMini has native USB-C, not a separate serial chip. |
| Pot does nothing / brightness jumps around | Pot on an ADC2 pin, or on a pin shared with something else | The pot must be on GPIO 1 (ADC1). GPIO 5 is ADC2 and goes unreliable with WiFi on — it's used here only as the I2C clock line, digitally. |
| Clock stuck at `--:--` | WiFi not connected, or NTP unreachable | Check the SSID/password (2.4 GHz network only — the ESP32-C3 has no 5 GHz radio); print `WiFi.status()` to Serial; confirm the router is not blocking UDP port 123. |
| Clock wrong by whole hours | Wrong POSIX time-zone string | Check `TIMEZONE_POSIX` against the target region's string (see [libraries-and-setup.md](libraries-and-setup.md)). The Open-Meteo time zone alone does not set the clock. |
| Encoder turns missed during weather refresh | The HTTP fetch blocks the loop for a second or two | Expected behaviour at one fetch per 10 minutes. If it matters, move the fetch to a separate task or accept the brief window. |
| Weather shows `-` for the condition | Unmapped WMO code | Check Serial for the numeric code, then add it to the table in [how-it-works.md](how-it-works.md) and `codeText()` in the sketch. |
| Weather page never fills in | HTTP error, or JSON parse failure | Read the Serial output: a non-200 HTTP code means the request failed (WiFi? URL typo — copy it from [how-it-works.md](how-it-works.md) exactly). "JSON parse failed" usually means the document is too small or the response was truncated: ArduinoJson v7's `JsonDocument` grows dynamically, but on v6 code raise the `StaticJsonDocument` size (try 2048–4096). Paste the URL in a browser to confirm Open-Meteo itself answers. |
| Encoder counts backwards | CLK/DT effectively swapped for your module's orientation | Swap the CLK and DT wires, or swap `ENC_CLK`/`ENC_DT` in code. Both are correct fixes. |
| Encoder double-steps or skips | Contact bounce, or the loop is busy when you turn | Keep the press debounce at 200 ms; for rotation, act only on one edge of CLK (the sketch uses the falling edge). If it still misbehaves at speed, move to the interrupt + 16-entry quadrature decode table method from the LastMinuteEngineers tutorial. |
| Screen too dim / patchy at low settings | Contrast floor too low — a panel trait, not a fault | The sketch already floors the pot at 8; raise that floor (e.g. map to 30–255) if your panel looks blotchy when dim. For "off", use `SSD1306_DISPLAYOFF` rather than contrast 0. |
| Nothing uploads | Charge-only USB cable, wrong port/board selected, or the board isn't entering download mode | Swap in a known data cable, pick the right port and "ESP32C3 Dev Module" in the IDE, and hold the BOOT button (GPIO 9) while starting the upload if the board needs it. |
