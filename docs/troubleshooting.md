# Troubleshooting

| Symptom | Likely cause | Fix |
| ------- | ------------ | --- |
| OLED stays black, Serial says "not found at 0x3C" | Wrong I2C address (some modules are 0x3D), SDA/SCL swapped, or your board's default I2C pins aren't 21/22 | Run an I2C scanner sketch to find the real address; swap SDA/SCL and retest; run the SDA/SCL print sketch in [wiring.md](wiring.md) and set `OLED_SDA`/`OLED_SCL` to match. Also confirm VCC is on 3V3, not 5V. |
| DHT page says "No reading" / values never update | DATA on the wrong pin, VCC/GND swapped, or reads happening too fast | Check DATA → GPIO 4; confirm you're using the module (with pull-up), not a bare sensor; keep the 2-second interval and the `isnan()` guard — frequent NaN bursts on a correctly wired DHT11 usually mean it's being polled too often somewhere. |
| Clock stuck at `--:--` | WiFi not connected, or NTP unreachable | Check the SSID/password (2.4 GHz network — ESP32 doesn't do 5 GHz); print `WiFi.status()` to Serial; confirm the router isn't blocking UDP port 123. |
| Weather page never fills in | HTTP error, or JSON parse failure | Read the Serial output: a non-200 HTTP code means the request failed (WiFi? URL typo — copy it from [how-it-works.md](how-it-works.md) exactly). "JSON parse failed" usually means the document is too small or the response was truncated: ArduinoJson v7's `JsonDocument` grows dynamically, but on v6 code raise the `StaticJsonDocument` size (try 2048–4096). Paste the URL in a browser to confirm Open-Meteo itself answers. |
| Encoder counts backwards | CLK/DT effectively swapped for your module's orientation | Swap the CLK and DT wires, or swap `ENC_CLK`/`ENC_DT` in code. Both are correct fixes. |
| Encoder double-steps or skips | Contact bounce, or the loop is busy when you turn | Keep the press debounce at 200 ms; for rotation, act only on one edge of CLK (the sketch uses the falling edge). If it still misbehaves at speed, move to the interrupt + 16-entry quadrature decode table method from the LastMinuteEngineers tutorial. |
| Screen too dim / patchy at low settings | Contrast floor too low — a panel trait, not a fault | The sketch already floors the pot at 8; raise that floor (e.g. map to 30–255) if your panel looks blotchy when dim. For "off", use `SSD1306_DISPLAYOFF` rather than contrast 0. |
| Nothing uploads | Charge-only USB cable, wrong port/board selected | Swap in a known data cable, pick the right COM port and board in the IDE, and hold BOOT while starting the upload if your board needs it. |
