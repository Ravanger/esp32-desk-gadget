# Troubleshooting

| Symptom | Likely cause | Fix |
| ------- | ------------ | --- |
| OLED stays black, Serial says "not found at 0x3C" | Wrong I2C address (some modules are 0x3D), SDA/SCL swapped, I2C wired to the classic-ESP32 pins 21/22 or the C3's risky 8/9, or VCC/GND swapped on the module | On the SuperMini, SDA must be GPIO 4 and SCL GPIO 5, and the sketch must call `Wire.begin(OLED_SDA, OLED_SCL)` with those defines set to 4 and 5. GPIO 8 (strapping + onboard LED) and GPIO 9 (strapping + BOOT) are not I2C pins for this build. The sketch probes 0x3C at boot and, if nothing answers, repeats "OLED not found at 0x3C - check wiring/address" on Serial every 2 s and stops. Run an I2C scanner sketch to find the real address — the sketch hardcodes 0x3C, so a 0x3D module needs a code change, not just a rewire. Also confirm VCC is on 3V3, not 5V, and read the module silkscreen: some modules swap VCC and GND pin order. If the display lights but is shifted or garbled with correct wiring and address, suspect SH1106 (132×64 RAM, different mapping, needs its own driver) — many 1.3-inch panels sold as "SSD1306" are actually SH1106; check the driver chip, not the size. |
| DHT page says "No reading" / values never update | DATA on the wrong pin, VCC/GND swapped, or reads happening too fast | Check DATA → GPIO 3; confirm the module version (with pull-up) is used, or add a 4.7 kΩ pull-up between DATA and VCC for a bare sensor (3-pin modules differ in pin order — read the silkscreen); keep the 2.5-second interval and the `isnan()` guard — frequent NaN bursts on a correctly wired DHT11 usually mean it is being polled too often somewhere. After a reboot there is no last good value, so the page shows "No reading" until the first successful read. Note the sensor's ±2 °C / ±5 % RH accuracy: small disagreements with another thermometer are expected, not a fault. |
| Serial Monitor shows nothing at all, or misses the first lines | USB CDC On Boot is off, the wrong board/port, or the monitor reconnected after a reset | Select "ESP32C3 Dev Module" with Tools → USB CDC On Boot enabled (the verified path), or "Nologo ESP32C3 Super Mini" (arduino-esp32 3.x, CDC on by default, not yet compile-verified with this sketch), and re-upload. On native USB the monitor reconnects after reset, so the earliest lines can be missed — press RESET with the monitor already open. |
| Pot does nothing / brightness jumps around | Pot on an ADC2 pin, pot not wired (floating GPIO 1), or a pin shared with something else | The pot must be on GPIO 1 (ADC1). GPIO 5 is ADC2 and must not be used for analog input on this build at all (ESP-IDF: ADC2 oneshot mode is no longer supported due to hardware limitations, results not stable) — it's used here only as the I2C clock line, digitally. With no pot wired, GPIO 1 floats and brightness wanders; wire the pot or tie GPIO 1 to 3V3 (reads full scale = full brightness). The ADC reads full scale above about 2.5 V (0–2500 mV effective range at 11 dB), so on a pot across 3V3 the top ~24% of travel is full brightness — that is expected, not a fault. |
| Clock stuck at `--:--` | WiFi connected but NTP not yet synced, or WiFi failed | `--:--` means NTP has not synced yet, not necessarily a WiFi failure. A WiFi failure shows "Connecting WiFi..." then the clock page with `--:--`, and Serial prints "WiFi: connection failed (30 s timeout)" — the sketch continues anyway and recovers on its own when WiFi comes up. Check the SSID/password (2.4 GHz network only — the ESP32-C3 has no 5 GHz radio) and confirm the router is not blocking UDP port 123. The clock never blocks, so the rest of the gadget keeps working meanwhile. |
| Button / TTP223 press does the opposite, or steps pages | Button logic misunderstood; TTP223 default is active-HIGH | A press jumps to Summary, a second press returns to Clock — it never steps through pages. A default TTP223 is active-HIGH, backwards for the sketch's active-LOW logic: solder jumper A for active-low, or invert the logic — not both. Never wire a button/TTP223 on GPIO 10 at the same time as the encoder's SW pin. |
| PIR holds the display awake, or blanks late | Module delay pot / H-L jumper, warm-up, or PIR wired but `USE_PIR` still 0 | The display blanks 60 s after the PIR's output drops ([how-it-works.md](how-it-works.md#optional-pir-sleep)); the module's delay pot (5–300 s) adds to that. Set the delay pot to minimum for the shortest time, allow about a minute of warm-up after power-up, and check the H (repeatable) / L (non-repeatable) jumper. A wired PIR does nothing until `USE_PIR` is set to 1 (default 0). Turning or pressing the encoder also wakes the display. |
| Display blanks about a minute after boot | `USE_PIR` is 1 but no PIR is wired to GPIO 0 (the pin is a pull-down input and never goes HIGH) | Set `USE_PIR` to 0, or wire the PIR. |
| Display flickers during weather fetches, or WiFi drops | Power droop during WiFi TX peak | TX peak is 335 mA (datasheet) and total peak draw is about 360–375 mA. The SuperMini regulator rating varies by clone (500 mA is quoted for ME6211-type parts; reports of 250 mA parts exist), and a weak USB port or cable adds to it. Set `WIFI_LOW_TX_POWER` to 1, add 10–100 µF across 5V/GND, use a short good cable, and measure total current with a USB meter during a fetch. See the power budget in [verified-specs.md](verified-specs.md). |
| SuperMini will not join WiFi, or drops often | 5 GHz-only network, wrong credentials, antenna interference, or the board's known TX-power issue | Use a 2.4 GHz network, check `WIFI_SSID`/`WIFI_PASSWORD`, keep wires away from the antenna end of the board, and set `WIFI_LOW_TX_POWER` to 1. The TX-power workaround is community-reported, not an Espressif recommendation. |
| Clock wrong by whole hours | Wrong POSIX time-zone string | Check `TIMEZONE_POSIX` against the target region's string (see [libraries-and-setup.md](libraries-and-setup.md)). The Open-Meteo time zone alone does not set the clock. |
| Encoder turns missed during weather refresh | The HTTPS fetch blocks the loop (4 s connect + 4 s TLS handshake + 4 s read timeouts: typically a few seconds when it fails, at worst about 12 s plus DNS lookup time) | Expected behaviour: one fetch every 10 minutes after success, every 60 s after a failure. If it matters, move the fetch to a separate task or accept the brief window. |
| Weather shows `-` for the condition | Code not in Open-Meteo's table | Check Serial or the Open-Meteo reply for the numeric code. The sketch maps exactly the 29 codes in Open-Meteo's official table (see [how-it-works.md](how-it-works.md)); any other value shows `-`. Do not add codes that Open-Meteo does not report. |
| Weather page never fills in | WiFi not connected yet, HTTP error, or JSON parse failure | The first fetch runs as soon as WiFi is connected, then retries every 60 s after a failure. Read the Serial output: a non-200 HTTP code means the request failed (WiFi? URL typo — copy it from [how-it-works.md](how-it-works.md) exactly); "JSON parse failed" or "missing fields" means the reply was truncated or unexpected. Paste the URL in a browser to confirm Open-Meteo itself answers. |
| Encoder counts backwards | CLK/DT effectively swapped for your module's orientation | Swap the CLK and DT wires, or swap `ENC_CLK`/`ENC_DT` in code. Both are correct fixes. |
| Encoder double-steps or skips | Contact bounce, or the loop is busy when you turn | For rotation, act only on one edge of CLK (the sketch uses the falling edge). The press is edge-triggered (HIGH→LOW) with a 200 ms guard, so holding it does not re-trigger. If it still misbehaves at speed, move to the interrupt + 16-entry quadrature decode table method from the LastMinuteEngineers tutorial. |
| Screen too dim / patchy at low settings | Contrast floor too low — a panel trait, not a fault | The sketch already floors the pot at 8; raise that floor (e.g. map to 30–255) if your panel looks blotchy when dim. For "off", use `SSD1306_DISPLAYOFF` rather than contrast 0. |
| Nothing uploads | Charge-only USB cable, wrong port/board selected, or the board isn't entering download mode | Swap in a known data cable and pick the right port and board ("ESP32C3 Dev Module" or "Nologo ESP32C3 Super Mini"). To force download mode, hold BOOT (GPIO 9), tap RESET, upload, then press RESET; the port may change in download mode. |
